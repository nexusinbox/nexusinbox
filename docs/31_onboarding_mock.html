エージェントに名前を付けましょう

エージェントは、あなたの代わりにメッセージをやり取りする窓口です。

相手にも表示されます。あとで変えられます。

どこで動かしますか？

あとから変えられます。迷ったら「このブラウザだけ」で始めてください。

このブラウザだけかんたんメッセージの読み書きは、この画面で行います。自動返信は、この画面を開いている間に動きます。
自分のパソコンでも動かすブラウザを閉じていても、自動返信や AI との連携を続けます。パソコンに小さなプログラムを入れます。

パソコンとつなぎます

ターミナルで次のコマンドを 1 回実行してください。この画面はそのままで大丈夫です。

nexusinbox connect 7KQ-4PZ
  1. 実行すると、パソコンの中の鍵を守るパスフレーズを決めるよう聞かれます。
  2. つながると、この画面が自動で切り替わります。

コード 7KQ-4PZ は 10 分間、1 回だけ使えます。シークレットを手で写す必要はありません。

届いた依頼にどう対応しますか？

細かい条件は、あとで「詳細設定」から変えられます。

まず私が確認するおすすめ依頼は受信箱の「承認待ち」に入ります。返事はあなたが決めます。
連絡先からの日程調整は、自動で承諾する登録した相手からの日程調整だけ、候補の最初の時間で承諾します。それ以外は確認待ちです。
日程調整は、自動で承諾する誰からの日程調整でも、自動で承諾します。

試してみましょう

自分宛てに日程調整の依頼を 1 通送って、届くか・どう対応するかを確かめます。

✓届きました
✓選んだ設定どおり「承認待ち」に入りました

準備ができました

「秘書」が使えるようになりました。

  • 受信箱で、届いたメッセージと依頼を確かめられます。
  • エージェントの画面に「パソコン: 接続中（2 分前）」「自動返信: 最後の対応」が表示されます。
  • AID や鍵などの技術的な情報は、エージェントの画面の「詳細」にまとめてあります。

今回の検証からの変更点

  • 手順は 1 本道。用語（DID・AID・credential・鍵の所在・Bridge）は出さない
  • シークレットのコピーをやめ、短い接続コードにする
  • 長い起動コマンドをやめ、コマンド 1 つにする
  • つながったか・自動返信が動いたかを画面で見せる
  • 自動返信はポリシー編集ではなく3 つの選択肢から選ぶ
  • 最後に自分宛てのテストで動作を確かめる

実装に必要なもの

  • 接続コード: 短命・1 回限り・試行回数の上限つきで、サーバ側で登録用シークレットに対応させる
  • nexusinbox connect <コード>: 登録と起動を 1 つにした入口（今の --enroll --dir と start <dir> をまとめる）。配布方法（Homebrew など）も決める
  • 接続状態: デーモンの最後のトークン発行時刻などから「接続中 / n 分前」を出す API
  • 自動返信の 3 択を、今のポリシー（JSON）に対応づける
  • 自分宛てのテスト送信と、その結果の表示

今あるもの: --enroll --dir と start <dir>（今日の 1 歩目）。ここからこの形に寄せていきます。
