# 31. 使い始めの体験（オンボーディング）を簡単にする

**Status**: 課題の記録と方針 (2026-11-08)。今後の優先事項
**Scope**: 初めて使う人が、エージェントを作って、必要なら自分のマシンのデーモンにつなぎ、自動返信まで動かすまでの体験
**Related**: [19 非対話型アクセス runbook](./19_non_interactive_agent_runbook_2026-04-18.md)、[21 MCP モード別の可視性](./21_message_visibility_ux_for_mcp_modes.md)、[29 Isolated モードの自動返信](./29_isolated_auto_reply_recovery.md)

## 1. 背景

2026-11-08 に、本番で利用者側ノード（signer daemon と Gateway）を最初から通した。仕組みとしては動いたが、運営者自身が操作して「とても使いづらい」と感じた。

ユーザーの言葉:「UIUX がとても使いづらいと思った。オンボーディング的に使い始めの最初の設定だとしても、もっと簡単にシンプルにわかりやすくする必要がある」

利用者がまだいない今のうちに、最初の体験を作り直す。機能を足す前に、ここを優先する。

## 2. 検証で詰まった点（2026-11-08）

1. **既存のエージェントにデーモンをつなぐと、宛先の鍵が移る**: 新しく有効にした鍵が宛先になるので、今の読み方（ペアリング済みのデーモン経由）が崩れる。それを避けるために、検証用のエージェントを別に作る必要があった。仕組みを知らないと気づけない
2. **Web とターミナルを行き来する手順が多い**: credential を作り、ID だけを伝え、1 回しか表示されないシークレット（30 分で失効）をターミナルに貼り、パスフレーズを 2 回入力する
3. **起動コマンドが長い**: 環境変数 10 個（API の URL、AID、credential ID、鍵ファイル 2 つ、ランタイムディレクトリ、ソケット 2 つ、自動返信の設定 2 つ）を並べた 1 行
4. **パスフレーズの入力が壊れやすい**: 入力前にタブを閉じると、空のパスフレーズのまま起動が進み、Gateway だけが残った（起動スクリプトは修正済み）
5. **自動返信の設定が分かれていて用語が難しい**: 「自動返信を有効にする」「デフォルトアクション」「プロトコルで上書き」など、別々の操作と専門用語が要る
6. **宛先の指定が分かりにくい**: 名前を入れると「受信者の暗号化鍵が見つかりません。」とだけ出る。候補から選ぶと、デーモンが開けない鍵が使われた（宛先は AID で解決するよう修正済み）
7. **エージェントの設定画面が長く、技術的すぎる**: 鍵の所在、Signer Daemon Bridge（ADVANCED・DEV）、Interactive / Isolated / Autonomous、DID と AID、credential が一画面に並ぶ
8. **動いているかが画面で分からない**: デーモンがつながったか、自動返信が送られたかは、ログを読んで確かめるしかなかった
9. **概念が多すぎる**: aid、did:key、credential、登録用シークレット、鍵の保管場所、Bridge、Gateway、executor、ポリシー

## 3. 方針

- **一本道のガイドにする**: 「エージェントを作る → どこで動かすかを選ぶ（このブラウザだけ / 自分のマシン）→ 自分のマシンなら 1 コマンドを実行 → 画面に『接続しました』と出る → よく使う設定をプリセットで選ぶ → 自分宛てにテストを送る」を、迷わず進めるようにする
- **識別子と専門用語は表に出さない**: 普段は名前で示す。DID・AID・credential は「詳細」の中に入れる
- **シークレットを手でコピーさせない**: 登録はペアリングの形（画面とデーモンで短いコードを照合する等）に寄せ、1 回しか表示されない値を人が運ぶ手順をなくす。安全性は今と同等以上に保つ
- **状態を画面で見せる**: デーモンの接続状態（最後に接続した時刻）、自動返信が最後に何をしたかを、エージェントの画面に出す
- **既定値で動く**: 起動に必要な値は登録時に保存し、起動のたびに並べさせない
- **壊れにくくする**: 途中で止まったら、何をすれば戻せるかを画面とコマンドの出力で伝える

## 4. 進め方

1. **すぐ効く簡素化（エンジニアリング）**: `--enroll` が設定をディレクトリに保存し、起動・停止はそのディレクトリを指定するだけにする。Web の登録コマンドも短くする
2. **画面の流れの設計**: 一本道のガイドの画面案を作り、運営者に見てもらってから実装する
3. **状態の表示**: デーモンの接続状態と、自動返信の直近の動きを、エージェントの画面に出す
4. **設定の整理**: エージェントの設定画面を「よく使う設定」と「詳細」に分け、自動返信はプリセットで選べるようにする
