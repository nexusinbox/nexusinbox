# 34. 受信箱の画面と説明文を分かりやすくする

**Status**: 洗い出しと進め方 (2026-11-08)。§3 の 1 (言葉を揃える) と 3 (受信箱の作り) は済み。2 は一部、4 はこれから
**Scope**: 受信箱 (Gmail 風の画面)、承認待ち、作成画面、ヘルプ、監査ログの言葉と構成
**Related**: [31 使い始めの体験](./31_onboarding_ux.md)

運営者の指摘: 「Gmail 風の UIUX や説明書きが難しくて理解しづらい」。2026-11-08 に、画面と日本語の文言をすべて洗い出した。専門用語 (DID、AID、Daemon、MCP、Phase など) は、ヘルプに 135 箇所、エージェント設定に 99 箇所、受信箱に 54 箇所、監査ログに 44 箇所あった。

## 1. 影響が大きい順

1. **受信箱が 2 つあり、自動返信は片方でしか動かない**。ホームの「受信トレイ」では動かず、「エージェント別」の受信箱を開いている間だけ動く。受信トレイの画面にはそう書かれていない。どのエージェントに届いたかも出ない
2. **承認待ちの画面が、暗号化された件名をそのまま見出しに出していた** (不具合。2026-11-08 に修正済み)
3. **このブラウザで読めないメッセージの説明が専門用語だらけ**: 「Signer Daemon プロセス内に閉じている」「MCP runtime で確認」「Daemon 管理」など
4. **同じものの呼び名が画面ごとに違う**
   - 動く場所: はじめての設定は「このブラウザだけ／自分のパソコンでも」、ヘルプと設定は「Interactive（推奨）／Autonomous」。「推奨」が画面によって逆を指している
   - アドレス: 「エージェントアドレス」が AID の意味でも DID の意味でも使われている
   - 承認待ち: 「承認待ち」「迷惑メール」「人間の承認待ちに入れる」(自動返信の設定) が重なっている。最後のものは、実際は承認待ちではなく受信箱に残す
5. **Gmail の真似がエージェントの受信箱に合っていない**
   - 「下書き」: 下書きを保存する機能がなく、いつも空
   - 「スター付き」: 左の一覧と絞り込みの両方にある
   - 左の一覧は 13 項目。監査ログやブロック設定まで並ぶ
   - 画面の見出しがなく、どの受信箱にいるのか分からない
6. **送る相手を AID か did:key で手入力させる**。候補は入力を始めるまで見えない
7. **名前の代わりに `did:key:z6Mk…` が出る**。知らない相手、作成画面の差出人、返信元の UUID、監査ログの生の JSON
8. **開発の段階名や内部名が画面に漏れている**: 「(Phase 4.4d、未稼働)」「(ADR 25e)」「schedule_negotiation · propose」「evaluator / executor」など。「未稼働」は古く、実際には動いているものもある
9. **ヘルプが開発者向け**: 鍵の回転、AES-GCM-256、Cloudflare R2、Bridged restore の説明から始まる。見出しの一部が英語

## 2. 言葉の決まり (これに揃える)

| いまの言葉 | これからの言葉 |
|---|---|
| Interactive / Autonomous / Daemon 管理 | 「パソコンで動いている」「このブラウザで動いている」(はじめての設定と同じ) |
| エージェントアドレス (AID) | アドレス |
| エージェントアドレス (DID)、did:key | 技術 ID (「詳細」の中だけ) |
| 人間の承認待ちに入れる (queue_for_human) | 自分で返事する |
| 承認待ち | 確認が必要 (届けてよいか、あなたが決めるもの) |
| schedule_negotiation / task_delegation | 日程調整 / タスク依頼 |
| MCP runtime、Signer Daemon、Gateway | パソコン、パソコンの AI ツール |
| Phase・ADR の番号 | 書かない |
| 監査ログ | AI の操作履歴 |

## 3. 進め方 (おすすめの順)

1. **言葉を揃える** (画面の作りは変えない): §2 の決まりで受信箱、作成画面、承認待ち、監査ログ、設定の文言を直す。段階名や内部名を消す。古い「未稼働」の表記は、実際の動きを確かめて直す
2. **小さな画面の手直し**: 知らない相手を「未登録の相手」と出し、コンタクトに追加できるようにする。差出人の DID を隠す。「AI下書きを承認」を「AI で返信を下書き」にする。エージェント別のバッジを未読数にする
3. **受信箱の作りを直す** (画面案を先に見せる): 受信箱を 1 つにまとめ、エージェントで絞り込む。どのエージェントに届いたかを各行に出す。自動返信がどこで動くかを画面で示す。左の一覧を「受信 / 送信済み / 確認が必要 / アーカイブ」程度に減らす。作成画面の宛先は、連絡先と自分のエージェントから選ぶ形にする
4. **ヘルプを書き直す**: はじめての設定と同じ言葉で、使う人向けの説明に絞る。暗号や API の話は開発者向けのページに分ける

## 4. 済んだこと

- 承認待ちの画面が暗号化された件名を出していた不具合を直した
- §3 の 1: §2 の決まりで、受信箱、作成画面、確認が必要 (旧: 承認待ち)、AI の操作履歴 (旧: 監査ログ)、エージェント設定の文言を直した (日本語・英語で 84 箇所)
  - 段階名・ADR 番号・内部名 (evaluator、Daemon、MCP runtime、Bridged restore、schedule_negotiation など) を消した
  - 「空いていれば承諾」は「このブラウザで Google カレンダーを連携しているとき」に動く、「AI に任せる」は「まだ使えません」と、実際の動きに合わせた (以前は両方「未稼働」)
  - 動く場所の呼び名を「パソコン」「このブラウザ (または AI ツール) だけ」に揃え、設定画面の「推奨」の食い違いをなくした
  - ブロックの段階を「この相手だけ / この人のすべてのエージェント / 完全に非表示」にした
- §3 の 3 (画面案 `docs/34_inbox_and_drafts_mock.html`、運営者の承認: 「この案で、全て推奨でOK」):
  - 左の一覧を「受信 / 確認が必要 / 送信済み / アーカイブ」と「連絡先 / エージェント / AI の操作履歴」にした。スター付き、下書き (いつも空)、すべてのメール、迷惑メール、ゴミ箱、エージェント別、ブロック設定、エージェント作成は一覧から外した (URL では開ける。エージェントの作成は「エージェント」から)
  - 受信箱は 1 つのまま、上の札でエージェントごとに絞り込む。2 つ以上エージェントがあれば、各行にどのエージェントの行かを色付きの札で出す
  - 自動返信がどこで動くかを受信の上に出す。このブラウザに鍵があるエージェントの自動返信は、エージェント別の画面だけでなく受信箱を開いている間も動くようにした
  - 「確認が必要」に「AI が作った下書き」(docs/33 §9) と「届いたメッセージ」を並べた。ボタンは「受信に入れる / 捨てる」
- §3 の 2 のうち: 名前の分からない相手は、did:key の切れ端ではなく「未登録の相手」と出す。自分のエージェントは、パソコンの鍵の DID でも名前で出す
- 作成画面の宛先 (2026-11-08、画面案 `docs/33_oauth_mock.html` の ④): 入力しなくても、連絡先と自分のエージェントの候補が出る。選ぶと「宛先: 名前」と出す。差出人の欄から DID を外した
- 残り: なし (ヘルプは下の §3 の 4)。エージェント別のバッジ (§3 の 2) は、エージェント別の一覧をなくしたので不要になった
- §3 の 4 (画面案 `docs/34_help_mock.html`、運営者の承認: 「全部推奨どおりでOK」、2026-11-09):
  - `/help` を使う人向けに書き直した: できること / はじめかた / 毎日の使い方 / AI につなぐ / 安全のしくみ / 困ったとき / 言葉。言葉ははじめての設定と画面に揃えた
  - 「AI につなぐ」にクラウドの AI の手順を入れた。Muse は設定ではなくチャットで頼む (例文つき)、Claude は「カスタムコネクタを追加」
  - これまでのヘルプ (動作モード、MCP の設定、API・SDK、暗号の用語) は、手を入れずに `/help/developers` へ移した。どちらもログインなしで読める (公開リポジトリに同じ内容がある)
  - 古いリンク `/help#help-modes` は、「このブラウザだけ」と「パソコンでも動かす」の違いの項目に着く
  - 書いている途中で見つけたこと: 緊急停止がクラウドの AI の許可を残していた。緊急停止で許可もまとめて切り、「クラウドの AI」もオフにするようにした (API、DB テストあり)
