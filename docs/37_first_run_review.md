**画面案**: `docs/37_first_run_mock.html`

**Related**: [31 オンボーディング](./31_onboarding_ux.md)、[35 画面の作り直し](./35_social_ui.md)、[36 紹介ページの画面案](./36_share_mock.html)

## 1. 確かめたこと

手元 (api-e2e / web-e2e) で、新しい利用者として表示名 → はじめての設定 (このブラウザだけ、まず私が確認する、テスト送信) → メッセージ → エージェント → パソコンをつなぐ画面 → 新しい会話 まで通した。テストの依頼は届き、設定どおりの判定になった。World ID の画面は本物の部品なので飛ばした。

## 2. 見つけたことと直したこと

| 見つけたこと | 直したこと |
|---|---|
| 作ったあと、話す相手がいない。設定の最後は「準備ができました」だけ。新しい会話の宛先は自分のエージェントだけで、名簿も無い | 「相手を招く」カード (`InviteCard`) を、設定の最後と、コンタクトがいないときの新しい会話に出す。「紹介リンクを作る」で紹介ページをオンにし (エージェント画面の「紹介する」と同じ)、共有する文とリンクを出す。押す前に、何が見えるようになるかを書く |
| 最初の画面の手順 ② に `` `aid:ai:...` `` が記号のまま出る | 「② 相手を招く」に置き換え、アドレスの話をやめた |
| 設定の最後の「受信箱へ」と、エージェント画面の「受信箱を開く」が、作り直す前の受信箱 (`/agent/<did:key>`、「マスタースイッチ OFF」の表示) を開く | 新しい「メッセージ」を開く。`/?agent=<DID>` で、そのエージェントに絞った状態から始まる |
| 自動返信の選択肢などが「連絡先」、ナビは「コンタクト」 | 日本語の画面の「連絡先」をすべて「コンタクト」にそろえた |
| 設定の途中で、タブの題が「はじめての設定」から一般の題に戻る。ほかの画面も、画面内の移動のあと一般の題になる | Next が移動のたびに layout の題を入れ直すため。`AppShell` が `<head>` の変化を見て、ページの題を入れ直す |
| 「自動返信は、このエージェントの受信箱を開いている間に動きます」 | いまは「メッセージ」を開いている間に、ブラウザのエージェント全部の自動返信が動く (`InboxAgentBar`)。文言を合わせた |
| 新しい会話で、自分のエージェントの行に AID が出る | 「自分あてに試すとき」と出す |

## 2.1 あとから直したこと (2026-11-10)

- エージェントがあってメッセージがまだ無いときの「メッセージ」画面が、AID とそのコピーを出していた。「相手を招く」カードに置き換えた
- その画面の「テスト送信する」は古い作成画面 (「E2E暗号化」の札つき) を開いていた。「自分あてに試す」にして、自分のエージェントとの会話 (`/?with=<AID>&as=<DID>`) を開く

## 3. 別に相談すること (この見直しには入れていない)

- **パソコンをつなぐと、ブラウザで本文が読めなくなる**: エージェントの暗号化の鍵が 1 つだけで、パソコンの鍵が宛先になるため (docs/31 §2 の 1)。送る側が「相手のエージェントの有効な鍵すべて」に包めば、ブラウザとパソコンの両方で読める (メッセージアプリの複数端末と同じ形)。設計を書いてから
- **パソコン側は、ターミナルと Homebrew が前提**: 再起動のたびにパスフレーズを入れて起動し直す (自動起動なし)。Windows は未対応 (docs/32 §5、「利用者の声が出てから」)
