流れ

  • ログイン前の説明 → World ID → ①どの AI と使うか → ②連絡先を作る → ③AI とつなぐ → ④どこまで任せるか → ⑤試す → ⑥準備状況 → ホーム。
  • 「まず Web で試す」は ③ を飛ばす（6 ステップの表示は 5 になる）。
  • ログイン前の画面は、見た目（今の暗い背景のページ）はそのままで、文言と並びだけを変える。この案は内容の確認用に白で描いている。
  • どこで止めても、次に開いたときはサーバの設定と端末の鍵から判定して「続きから」を出す。作ったエージェントを二重に作らない。
  • ⑤ の 4 つの確認（受信・Web で読む・AI で読む・自動返答）は別々に表示し、一部だけ成功しても「完了」とは言わない。待ち時間を過ぎたら「まだ確認できません」と出し、失敗とは言わない。

決まったこと（2026-11-15）

  • Muse・Claude Desktop・Claude Code は、すべてコネクタの URL 方式でつなぐ。できるのは読み取りと下書きまでで、送信は本人が確かめる（選択肢と完了画面に明記）。ローカルの MCP は開発者向けのページに残す。
  • 実機で初回接続・読み取り・下書き・接続し直し・連携の解除を確かめたものだけを正式な選択肢にする。確かめるまでは「確認中」と出し、選べなくする（docs/41 §5.2.1 に記録）。Claude Code は 2026-11-15 に 5 項目を確かめたので選べる。Muse（接続し直し・連携の解除が残る）と Claude Desktop は確認中。
  • パソコンが要ることは選ぶ前に、理由（パソコンが通信を担当）と条件（使っている間は起動）を添えて出す。
  • スマホでは作る前に止め、「パソコンでこのページを開く」（URL のコピー）と「このスマホで Web だけ試す」を出す。進捗は引き継がないので「続ける」とは書かない。
  • AI の読み取りは本人が「AI にテストメッセージが表示された／表示されなかった」で確かめる。接続の許可（自動で確かめる）とは別の行にし、「あとで確かめる」も選べる。
  • ログイン前の画面は見た目を変えず、文言と並びを変える。
  • つなぐ前に届いたメッセージは、AI からは本文を開けない。「受信したときの鍵があるブラウザや端末で確認してください」と案内する。
  • パソコンの「接続しました」は、start の表示ではなく、API に届いた実際の接続で判断する。
